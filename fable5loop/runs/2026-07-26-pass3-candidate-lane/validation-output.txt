================================================================
DESIGN POINTS WORTH RECORDING
================================================================

Drift is keyed on entity identity, not array position (`ENTITY_KEYS`). Keying on
position would report a section reorder as drift for every downstream row — the
wrong-key artifact-diff failure mode already recorded in the skill. Collections
without a known identity column are compared as order-insensitive multisets.
Only `generated_at` / `sourceGeneratedAt` / `generatedAt` are ignored.

Stage 3 runs `validate_workbook_schema(..., check_live_contract=False)`. The live
check compares against the *published* tree, which a candidate has no business
being measured against; the candidate's registry is proven at stages 8 and 9
instead.

The harness override is a single named fact shared by both sides
(`CORVETTE_FORM_DATA_JS`), and the harness has **no fallback** when it is set:
silently reading the published `form-app/data.js` would let stage 9 pass while
proving nothing about the candidate. Two tests pin this — one asserts the harness
fails against a deliberately empty candidate registry, one asserts the env var
name matches on both sides.

`execute_promotion(..., run_candidate_lane=False)` exists for the promotion
bookkeeping tests, whose fixture workbook is a minimal scaffold and not
generatable. The CLI never passes it.

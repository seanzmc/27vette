## Fix 1 — cross-model rule is a UNION, not an intersection

An intersection was defeated by two ordinary authoring actions: dropping the same step from two
models, or deactivating a single peer row. A union survives both, because every remaining peer still
demands the step.

**Disclosed limit, weaker than bdf6690 for promoted models in exactly one case:** dropping a step
from EVERY active model passes, because nothing is left to compare against. The old Python
`STEP_ORDER` tuple caught that for promoted models. `summary` is the only step with no model-scoped
workbook reference — `step_order_summary_map` covers the other 13 — so `summary` is the only key
exposed. Closing this needs a model-scoped workbook reference to the summary step; until then it is
recorded here rather than framed as intended behavior.

## Fix 2 — the test no longer passes on the intersection source alone

`test_dropping_any_single_runtime_step_fails_generation` now covers all six models (84 subtests) and
asserts on the completeness message with `assertRaisesRegex`, not a bare `ValueError`. Two cases
added: `test_dropping_one_step_from_two_models_still_fails` (pins the union), and
`test_workbook_scoped_sources_catch_a_step_no_peer_authors`, which strips `paint` from every model
so only `step_order_summary_map` can catch it — pinning the workbook-scoped sheets independently of
the cross-model rule. Without it, narrowing the check back to peer comparison alone would pass every
other case in the class.

## Fix 3 — split the conflated set

`UNAUTHORED_BUCKET_STEP_LABELS` served two purposes: supplying a label AND exempting a key from the
completeness guard. Cycle 2 demonstrated the hole — adding `{"paint": "Paint"}` made a dropped
`paint` row generate silently. Now `BUCKET_STEP_KEYS` (exemption) and `UNAUTHORED_BUCKET_STEP_LABELS`
(label) are separate.

## Fix 4 — blank step_label raises

`load_runtime_steps` did `clean(row.get("step_label")) or step_key`, so a blank cell shipped the raw
snake_case key as a customer-visible label (`steps[].step_label` renders at app.js:1965, 2612, 2677).
It now raises, matching the module docstring and `workbook_step_label`.

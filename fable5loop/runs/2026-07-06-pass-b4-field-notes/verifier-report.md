## Required Fixes Before Pass

None blocking. Recommended follow-ups (non-blocking):

1. **`NEW_MARKER_RE` over-broad** (`copy_split.py`): `r"^\s*NEW!*\s*"` matches zero `!`, so a future export line "New Emergency Kit, roadside" → name "Emergency Kit", and "Newly designed spoiler, carbon" → "ly designed spoiler" — silent, unflagged corruption. One-character fix: `NEW!+\s*` (require at least one `!`). Current export unaffected (all 62 hits are "NEW!").
2. **Duplicate-name flag is filter-scoped**: `review_queue` computes `duplicate_proposed_name` over the *filtered* scope, so with a source-group or search filter active, cross-group name collisions temporarily lose their flag. Harmless for the unfiltered exception sweep; worth computing over the pre-filter scope.
3. Cosmetic: `one_word_name` never fires when the name is the entire cell (no remainder) — defensible (nothing to rebuild from), but worth a comment or a Sean confirmation.
4. Consistency note: `completeness` still requires a price decision for `hold_for_question` section rows while `build_plan` treats held rows as price-exempt (inert). Stricter-than-plan is safe, just asymmetric with the skip path.

## Durable Lesson Candidates

- **Marker regexes for literal tokens should require the literal**: `X!*` silently degrades to a bare-word prefix strip; use `X!+` (or `re.escape` the exact observed marker) and add a negative test ("Newly…" must survive) whenever stripping decorations from source text.
- **Dedup/exception flags computed inside a filtered query change meaning with the filter**; compute collision sets over the full lane scope before applying view filters.
- **"Exempt from completeness" must be proven at three layers** — completeness counters, plan gaps, and plan coverage (uncovered-decision accounting) — the B.4 skip work needed all three (`skipped_ids`, reordered section/price gap checks, `inert_candidates`), and a test that flips a fully-reviewed row to skip catches the coverage layer that a fresh-skip test misses.
- **Model-scoped status reads**: on mixed multi-model sheets, any per-model judgement (SE gate, availability) must filter status cells by the model's own variant-column prefixes first; a fixture row that is S on one model and A on another (XFR/BC7 pattern) is the regression sentinel.
- **UI decision buttons must post the exact predicate the blocker checks** (here: any decision with `groupKey == variant_reconciliation` for the model); verifying that wiring means reading both sides, not trusting the label.

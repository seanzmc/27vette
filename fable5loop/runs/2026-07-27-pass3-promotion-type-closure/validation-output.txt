C3 / C4 / C5 / C6 — WHAT WAS REMOVED
================================================================

C3  `REGISTRY_PROMOTION_ARTIFACT_TYPES` is now `("runtime_contract",)`, with a
    new `DEFAULT_REGISTRY_PROMOTION_ARTIFACT_TYPE`. It is one tuple in
    `workbook_domain/registry.py`, and schema validation, promotion parsing, and
    the editor enum all derive from it — so the vocabulary cannot be narrowed in
    one module and left wide in another.

C4  A blank `artifact_type` cell now means `runtime_contract`. It used to mean
    `draft_artifact` — a review artifact promoted to production by omission.

    Scoped precisely: this is a real behavior change in the acceptance path
    (`registry_promotion.py`), and reverting that default there fails two tests.
    At the schema layer the default is cosmetic — a blank cell is already an
    unconditional `registry_promotion_blank_artifact_type` error before the
    default is consumed, and the defaulted value survives only inside another
    issue's payload. Reverting `schema_validation.py`'s default alone is
    therefore undetectable, and saying otherwise would overstate it.

C5  `artifact_path` is unconditionally required, in both `registry_promotion.py`
    and `schema_validation.py`.

    Falsifiability differs between the two files, and an earlier version of this
    receipt got it wrong by claiming neither was testable.

    `registry_promotion.py` — genuinely not falsifiable. The vocabulary check at
    line 121 RAISES before the path check at line 123, so with the narrowed
    vocabulary `artifact_type != "current_generation"` is unconditionally true
    there. Restoring the exemption leaves all promotion tests green. The
    exemption became dead the moment C3 landed; removing it is cleanup, and the
    vocabulary test is the real guard.

    `schema_validation.py` — IS falsifiable, and now tested. That layer
    accumulates issues instead of raising, so `artifact_type` can still be
    `current_generation` when the path check runs, and the exemption was live.
    Restoring it silently drops `registry_promotion_missing_artifact_path` for a
    blank-path row while every other test stays green. Proven:

      working tree:  {registry_promotion_missing_artifact_path,
                      registry_promotion_unknown_artifact_type}
      exemption restored:  {registry_promotion_unknown_artifact_type}   <- one lost

    Covered by `test_a_retired_type_with_a_blank_path_reports_both_defects`,
    which fails against the restored exemption (1 failed, 45 passed).

C6  Deleted outright:
      current_generation_artifact_path()
      promotion_requires_runtime_contract_assertion()   (was already zero-caller)
      load_promotion_data()
      build_registry_from_promotions()                  (requirement 8)
    `registry_promotion.py` went 312 -> 251 lines.
    `artifact_path_for_promotion()` survives because it has two real callers
    (`generate_registry.py` and `load_promotion_artifact_data`), and no longer
    branches — it is now the single place a promoted row becomes a file.

# Z06 Full Runtime Promotion Spec

## User goal

Promote Z06 to the full static app runtime first, then handle the other Z models later. This pass should make Z06 available in the live runtime registry alongside Stingray and Grand Sport while preserving the current Stingray/Grand Sport behavior and not promoting ZR1 or ZR1X.

## Diagnosis

Current repo evidence inspected:

- Branch/status:
  - Active branch: `z06-zr1-migration`.
  - Existing in-progress Z06 preview work is present:
    - `scripts/corvette_form_generator/model_configs.py`
    - `scripts/corvette_form_generator/inspection.py`
    - `scripts/generate_z06_form.py`
    - `tests/z06-contract-preview.test.mjs`
    - `tests/z06-form-data-draft.test.mjs`
    - `form-output/inspection/z06-*` artifacts.
  - Existing unrelated `.DS_Store` and `backups/` untracked files are present and should not be touched.

- Current runtime registry:
  - `form-app/data.js` currently exposes only:
    - `stingray`
    - `grandSport`
  - `z06` is not yet in `window.CORVETTE_FORM_DATA.models`.

- Workbook promotion controls:
  - `model_master` has Z06 row:
    - `model_key=z06`
    - `registry_key=z06`
    - `model_label=Z06`
    - `dataset_name=2027 Corvette Z06 future metadata scaffold`
    - `active=False`
  - `model_registry_promotion` has Z06 row:
    - `promoted_to_runtime=False`
    - `active=False`
    - `artifact_path=None`
    - `display_order=3`
  - `variant_master` has six Z06 variants with real base prices and display order, but `active=False`:
    - `1lz_h07`
    - `2lz_h07`
    - `3lz_h07`
    - `1lz_h67`
    - `2lz_h67`
    - `3lz_h67`
  - `scripts/corvette_form_generator/registry_promotion.py` requires a promoted model to be active in `model_master`; otherwise it raises.

- Current Z06 source quality from workbook inspection:
  - `z06_options` has 249 option rows.
  - Standard-equipment sections currently have zero priced rows in `z06_options` for:
    - `sec_stan_001`
    - `sec_1lte_001`
    - `sec_2lte_001`
    - `sec_3lte_001`
    - `sec_incl_001`
    - `sec_safe_001`
    - `sec_stan_002`
    - `sec_tech_001`
  - Z06 default-selected rows count: 4.
  - Z06 nonselectable default rows: 0.
  - Z06 missing `display_order` count: 0.
  - This means the specific standard-section/default-select/display-order regressions the user called out do not block Z06 promotion based on current sheet evidence, but they should remain protected by tests.

- Current Z06 draft artifact:
  - Generated by `scripts/generate_z06_form.py` into `form-output/inspection/z06-form-data-draft.json`.
  - Current draft status is intentionally non-live, but the same artifact shape is compatible with the existing Grand Sport promotion pattern: Grand Sport is already live through a draft artifact promoted by `model_registry_promotion` and cleaned by `live_contract_data()`.

Root cause / current blocker:

Z06 is not in the runtime because its workbook promotion controls are still inactive/unpromoted, its variants are marked inactive in `variant_master`, and `form-app/data.js` has not been regenerated with a promoted Z06 registry row. The prior Z06 pass intentionally stopped at non-live preview/draft artifacts.

Risk level:

- Medium-high because this pass changes the customer-facing model selector/runtime data registry.
- Dealer submission/download flows must preserve payload shape and endpoint while adding the model-scoped Z06 value.
- Workbook edits are required and must use the safe-save path.

Change type:

- Mixed workbook/data + generated artifact + runtime-registry + tests.
- No styling-only changes.
- No new dependencies.
- No runtime refactor intended.

## Exact files, sheets, and artifacts to change

Workbook source sheets in `stingray_master.xlsx`:

1. `model_master`
   - Set Z06 `active=True`.
   - Update Z06 `dataset_name` from scaffold/draft wording to an operational runtime label, e.g. `2027 Corvette Z06 operational form`.
   - Keep `default_model=False`.
   - Keep `registry_key=z06`.

2. `model_registry_promotion`
   - Set Z06 `promoted_to_runtime=True`.
   - Set Z06 `active=True`.
   - Set Z06 `artifact_path=form-output/inspection/z06-form-data-draft.json`.
   - Set Z06 `artifact_type=draft_artifact` to match the current Grand Sport promotion pattern.
   - Keep `default_model=False`.
   - Keep `display_order=3`.
   - Do not add/promote ZR1 or ZR1X rows.

3. `variant_master`
   - Set active=True for the six Z06 variants only:
     - `1lz_h07`
     - `2lz_h07`
     - `3lz_h07`
     - `1lz_h67`
     - `2lz_h67`
     - `3lz_h67`
   - Preserve base prices and display orders.
   - Do not change Stingray, Grand Sport, ZR1, or ZR1X variant rows.

Python/source files:

4. `scripts/corvette_form_generator/model_configs.py`
   - Update the Z06 fallback `dataset_name` and notes from draft/inactive wording to operational/runtime wording.
   - Keep sheet mappings and config shape unchanged.

5. New migration/apply script, proposed path:
   - `scripts/promote_z06_runtime.py`
   - It must use `save_workbook_safely()`.
   - It must be idempotent.
   - It must fail if the Excel lock file exists.
   - It must report exact row changes and verify saved workbook rows on disk.

Generated artifacts:

6. `form-output/inspection/z06-*`
   - Regenerate Z06 inspection/preview/draft artifacts after workbook activation.
   - Expected result: Z06 inactive-variant warning should disappear if `variant_master` activation is correct.

7. `form-app/data.js`
   - Regenerate via `.venv/bin/python scripts/generate_stingray_form.py` after Z06 promotion rows are active.
   - Expected runtime registry should include:
     - `stingray`
     - `grandSport`
     - `z06`
   - `defaultModelKey` should remain `stingray`.
   - `window.STINGRAY_FORM_DATA` alias should remain present and point to Stingray.

Tests:

8. Update/add Z06 runtime tests, likely in:
   - `tests/multi-model-runtime-switching.test.mjs`
   - and/or new `tests/z06-runtime-promotion.test.mjs`

Test assertions should cover:

- `window.CORVETTE_FORM_DATA.models.z06` exists after generation.
- Z06 model selector can be activated through the runtime test API.
- Z06 has 6 variants and active body/trim setup.
- Z06 default model is not default-selected at startup; Stingray remains default.
- Z06 dealer submission payload uses `modelKey=z06` / Z06 label without changing endpoint or payload shape.
- Z06 default-selected rows remain selectable in runtime data.
- Z06 standard-equipment sections do not contribute priced selectable review options.
- Z06 draft-only provenance fields are stripped from `form-app/data.js` by `live_contract_data()`.

Optional focused data test:

- Extend `tests/z06-form-data-draft.test.mjs` so generated Z06 data continues to prove:
  - no priced rows from standard-equipment sections;
  - default-selected options are selectable;
  - no missing display order in Z06 option rows.

## Constraints to preserve

- Visual preservation:
  - Do not change HTML/CSS layout or visual design in this pass unless a test exposes a generic runtime bug that blocks Z06 activation.

- No refactor:
  - Use the existing workbook-owned promotion path through `model_registry_promotion`.
  - Do not redesign the generator architecture.
  - Do not turn this into a ZR1/ZR1X promotion pass.

- No new dependencies:
  - Use existing Python/openpyxl helpers and existing Node test stack.

- Workbook source-of-truth:
  - Runtime promotion, variant activation, model label/year/export slug, and artifact path belong in workbook rows.
  - Do not hardcode Z06 into `form-app/app.js`.
  - Do not hand-edit generated `form_*` workbook sheets.
  - Do not hide Z06 source-data issues in Python or JavaScript; fix workbook source rows if surfaced.

- Dealer submission boundary:
  - Do not change endpoint:
    - `https://stingraychevroletcorvette.com/wp-json/corvette-build/v1/submit`
  - Do not change Turnstile behavior.
  - Do not change payload shape except that an already-supported model-scoped field should now carry Z06 when Z06 is selected.

- User boundary:
  - Promote Z06 to full runtime first.
  - Do not promote ZR1 or ZR1X in this pass.
  - Keep other Z-model promotion as a later pass.

## Risks and non-goals

Risks:

- Z06 may reveal runtime assumptions that only Stingray/Grand Sport exercised, especially around LZ trims, Z06 sections, Z07/package/wheel required groups, and interior grouping.
- Regenerating `form-app/data.js` will change a live runtime artifact; diff review must confirm only the intended registry/model payload change occurred.
- The current Z06 artifact is still named `z06-form-data-draft.json`; this mirrors the current Grand Sport promotion pattern but may be semantically confusing. Renaming artifact families is out of scope unless needed for correctness.
- Browser/manual verification is still required because Node runtime tests cannot fully prove the model selector UX.

Non-goals:

- No ZR1 runtime promotion.
- No ZR1X runtime promotion.
- No pricing-matrix cleanup beyond Z06 blockers found during validation.
- No section move pass for remaining cross-Z model cleanup unless it blocks Z06.
- No live deployment/publish command.
- No dealer endpoint/payload redesign.
- No CSS redesign.
